# 闲鱼二手选品方法论 / Xianyu Secondhand Sourcing

> 一套给 AI Agent 用的闲鱼（goofish）二手查找、比价与批量收藏方法论。
> 适用任何品类，不绑具体商品。**核心是六条可迁移技术 + 一套可复现的浏览器操作契约 + 一份跨品类的经验来源索引。**
>
> **定位**：不蹲漏、不追最低价。在你要**当场做决定**的时候，把「这件东西是不是真的」算清楚。
> 蹲漏是赌概率（监控工具的活），出配置是算约束（本 skill 的活）。

## 为什么需要这个

二手平台的坑不在"会不会搜"，而在**搜索结果会骗人**：

- 加了 `&page=5` 返回 200 和满屏数据，**内容其实是第 1 页**。5 组关键词 × 2 页采到 300 条，去重后只剩 88 条——不去重就会以为采了几百条，结论全错。
- 搜「B350M 迫击炮」返回的是**挂包、猫砂、钓台、健美操鞋**。平台把中文外号拆碎了。
- 同一个「降噪」，在耳机行内分裂成 **ANC / ENC / 物理降噪**三种互不等价的东西。
- 「8G×2 套装 ¥248」的描述小字写着「**标价单条！**」——实际 ¥496。
- 收藏点完按钮变成「已收藏」，但**请求其实失败了**（React 乐观更新）。

这些坑的共同点：**界面给了你一个"成功"的假信号**。这套方法论就是围绕"如何不被假信号骗"写的。

## 六条核心原则

| # | 原则 | 一句话 |
|---|---|---|
| 1 | **先白名单，后搜索** | 模糊需求直进搜索框 = 把噪声当候选。先翻成型号/关键词白名单，白名单由官网等权威源构建 |
| 2 | **同名不同质** | 每个品类都有会分裂的属性词，必须用官方规格证伪，不能读标题、不能靠型号后缀推断 |
| 3 | **导航控件会静默骗人** | `&page=N` 无效、价格筛选不改 URL、卡片选择器 hash 会变。**所有结论用"内容是否真的变了"验证** |
| 4 | **写操作的登录态只信 DOM** | cookie 存在 ≠ 会话有效。收藏必须做「按钮文案回读 + 收藏页 ID 交集」双层验证 |
| 5 | **卖家身份不决定风险，但决定"细节问谁问得到"** | 风险定价只看件上证据（SN/读数/温度/焊脚），不看商家还是个人；但**非标生活物品找个人**——商家批量走货不会逐个测试，只有个人会讲单件细节 |
| 6 | **先取时效性锚，再谈极限省钱** | 先抓近期第三方实测（装机视频/拆解/评测）定方案，再谈省钱。矿卡/魔改等替补默认作废 |

## 这个 skill 不做什么

先说清边界，比说清功能更有用。

**它不帮你蹲漏。** 等一个异常低价出现、有货了推你手机——那是监控工具的活（例如 [ai-goofish-monitor](https://github.com/Usagi-org/ai-goofish-monitor)）。它的 prompt 长这样：「我要 iPhone 15 Pro，95新，电池>90，6000以内」——单点偏好，蹲到就推。

**它不追最低价。** 求稳的代价是可能多花 200。**这个钱买的是「不会买错」，不是「买得最便宜」。** 如果不把这句话说在前面，用户会觉得「用了你的方法反而买贵了」。

**它不猜卖家。** 卖家身份不是风险变量，件上的证据才是。

**它只做一件事**：在你要**当场做决定**的时候，把「这件东西是不是真的」算清楚。

---

## 和监控工具的区别：求性价比 vs 求稳

这两件事的目标函数是**相反**的，不是程度不同。

| | 监控工具（蹲捡漏） | 本 skill（现场出配置） |
|---|---|---|
| **目标函数** | 找到异常低价 | 在这个预算下不出错 |
| **低价意味着** | 机会 → 加分 | 可疑 → 扣分 |
| **时间成本** | 可以等，蹲一周无所谓 | 当下就要决定 |
| **失败代价** | 错过一个漏，下次还有 | 买错一件，整机可能点不亮 |
| **解的形状** | 一个点（那张卡） | 一组互相锁死的件 |

**同一个信号，两边结论相反。**「价格低于市场价」——监控工具打高分推荐，本 skill 打红旗否决。这不是谁错：蹲漏的人本来就接受赌一把；要出配置的人不能赌，因为一件错会连坐整机。

### 第二层差异：单点比价 vs 带约束组合求解

真实场景长这样：

```
机箱 CPU限高 135mm  →  散热只能 132mm  →  彩蝶V4
主板 B550M = AM4    →  CPU 必须 AM4    →  R5 3600
机箱 显卡限长 240mm →  显卡 6500XT MECH 2X 刚好
```

**改任何一个件，其他全要重算。** 监控工具的 prompt 是单点偏好，没有约束串联；出配置天生是带约束的多点求解。

> **一句话**：蹲漏是赌概率，出配置是算约束。
> 他帮你等一个便宜，我帮你当场做对一个决定。

## 快速开始

把整个目录放进你的 Agent skills 目录即可（Claude Code / Codex / opencode / DSH 等通用）：

```bash
# 例如
cp -r . ~/.claude/skills/xianyu-secondhand-sourcing
# 或
cp -r . ~/.config/opencode/skills/xianyu-secondhand-sourcing
```

然后直接说需求：

```
闲鱼上帮我找 100 块以内带主动降噪的蓝牙耳机
帮我比价 RTX 6500XT，预算 700
把这几条挂单收藏了：<链接>
闲鱼登录不上 / 被风控了
```

Agent 会读 `SKILL.md`（通用流程）；**只有当品类是电脑配件时**才会额外读 `references/pc-parts.md`。

## 运行环境要求

**必须有浏览器自动化能力**（闲鱼是重前端 SPA，纯 HTTP 拿不到卡片数据）。

`SKILL.md` 的 `allowed-tools` 列的是参考实现，方法论本身不依赖具体工具名：

| 能力 | 参考实现 | 可替换为 |
|---|---|---|
| 开页面 / 切标签 | `ego_space_open` `ego_navigate` `ego_tabs` | Playwright `page.goto` |
| 页内执行 JS | `ego_js` `ego_script` | `page.evaluate` |
| 点击 | `ego_click` | `page.click` |
| CDP 原生命令 | `ego_cdp` | `context.addCookies()` / 裸 CDP |

## SKILL.md 里有什么

### 四个阶段

| 阶段 | 内容 |
|---|---|
| **1 · 构建白名单** | 读 App 商店描述抠官方支持清单；用官网关键词命中次数判"某规格到底有没有"（命中 0 次 ≈ 没有，几十次 ≈ 铁定有） |
| **2 · 闲鱼检索** | DOM 契约（属性选择器而非易变 hash）、价格分行正则、`&page=N` 陷阱与页面内翻页、价格筛选框、排除词模板 |
| **3 · 详情页核验** | 五要素抓取 + **读图核验**（先读卖家给的图，缺口才是要问的）+ **硬约束串联**（A 的尺寸决定 B 能不能装） |
| **4 · 登录与批量收藏** | Netscape cookie → CDP 注入、登录态 DOM 判定、收藏双层验证、profile 资产说明 |

### 两个反直觉的实测结论

**① `notLoginContainer` 不等于未登录。**
详情页「收藏」按钮的父链就包在 `notLoginContainer--*` 里，**已登录时也是这个 class**（只是布局包装）。曾据此误判"未登录"，白等 100 秒。权威判据只有一个——打开 `/personal` 看是否渲染出「我的闲鱼 / 我的交易 / 我的收藏 / 账户设置」。

**② 主动明示缺陷的卖家可信度更高。**
敢写「缺背板，后面有磕碰」「板载网卡坏了，送 USB 网卡」的，可信度**高于**满篇好话的。因为敢写瑕疵的人不怕你验。

### 附录 A · 耳机品类完整示例

`SKILL.md` 文末有一个 110 行的完整走查：从「一百块以内，要降噪，能连手机」开始，五步走到可下单清单，并附一张「耳机 / 电脑配件 / 球鞋」的填表对照——证明同一套结构换品类只是"填什么"不同。

| §7 | A–D 可信度分层（一票否决 / 强证据 / 参考 / 不采信） |
| §8 | 换品类时怎么复用这个索引结构 |

### 三条从 sources.md 里值得单独拎出来的

**① 确认收货 = 平台不再管你**
> 《闲鱼社区交易争议处理规范》第二十一条：「一旦交易成功，之后产生的纠纷争议闲鱼将不予受理。」

**② 验货宝不判断矿卡，也不管私聊承诺**
> 「买卖双方私下聊天内容内的承诺，不在服务商验货服务检验范围内。」

**③ 刷 BIOS 让 GPU-Z 截图失效了**
> 2026-09 实测报道：「注册表、魔改 VBIOS、定制驱动，三重手段让一张 4060 在系统和 GPU-Z 里都显示为 4070。」
> 所以：**现场跑 3DMark 对分数 + 烤机 15 分钟 + 显存专项检测**，三个都不认字体。

## 设计哲学

### 1. 只信可验证的证据

给每条挂单打级：

| 级 | 内容 | 例 |
|---|---|---|
| **L0 硬数据** | 可验证的数字 | 「甜甜圈占用 99%、温度 68℃」「健康度 88%、0E=0」「SN 官网可查」 |
| **L1 承诺** | 有兜底的条款 | 描述不符包邮退 / 只换不修 / 验货宝先验后买 |
| **L2 自述** | 只有形容词 | 「功能正常」「无暗修」「无矿」 |
| **L3 无** | 只有标题和价 | — |

**L2 以下不进推荐。**

### 2. 先读图，再提问

详情页商品图往往已经含有官方工具截图、S/N、参数表。**读得出来就不必再问；读不出来的那一项才是要问的。** 这一步能省掉一半以上来回，也是判断"卖家到底测没测过"的唯一办法。

### 3. 替补方案默认作废

矿卡、魔改卡这类"极限省钱"方案**默认不进任何推荐**，只在用户明确要求压预算时作为**单独成段的替补**出现，且必须标风险等级 + 验证动作。主方案永远以近期第三方实测为准——硬件行情迭代快，**知识库天生会过时**。

### 4. 风险定价 vs 信息获取：这是两件事

原则 5 曾经写得很绝对：「卖家身份不是风险变量」。这句话在**风险定价**上是对的，但它漏了一个真实差异——**你能不能拿到足够的细节，要看品类。**

**5a · 风险定价：不看身份，只看件上证据**

不管对面是商家还是个人，判据都是同一套：SN 能不能查、CDI 读数、烤机温度、焊脚颜色、规格对不对。**风险来自件，不来自人。**

**5b · 信息获取策略：要看品类**

| 品类类型 | 找谁 | 为什么 |
|---|---|---|
| **参数化商品**<br>电脑配件、摄影器材、工具、乐器零件 | **商家往往更可验** | 有备货、有测试台、有退换流程、能开票；个人只有一片件，测不了也没得换 |
| **生活物品 / 非标品**<br>家具、生活用品、收藏品、二手衣物、非标乐器 | **个人往往更好** | 商家批量走货，**不会逐个测试、也不会讲单件细节**；个人就这一件，能回答「滑轨顺不顺」「哪根品丝磨了」「这块木头有没有补过」 |
| **一体化品牌商品**<br>品牌整机、手机、笔记本 | **专门筛个人** | 商家会拆件翻新、拼装、换配件 |

**判据：这个品类的关键信息，能不能靠「硬数据」独立验证？**

- **能**（有 SN、SMART、跑分、官方规格表）→ 谁卖都行，甚至商家更好（有测试台）
- **不能**（没有可查编号、没有标准测试项，判断全靠实物细节）→ **个人卖家的「愿意细聊」本身就是信息源**

> 一把二手吉他，没有 SN、没有官方健康度。你唯一的信息来源就是卖家本人——「第 12 品有没有打品」「琴颈调过吗」「换过弦枕吗」。这种问题商家答不上来（他只管走货），个人能答。
> **这时「找个人」不是因为它更可信，是因为它是唯一的信息通道。**

**但 5b 只是「去哪问」，不是「问了就信」。** 个人卖家的回答仍然只是 **L2 自述**，必须靠照片/视频升到 L0。

**5c · 统一出口**：不管对面是谁，最终都打 L0–L3 证据级，**L2 以下不进推荐**。

## 适用范围

**适用**：闲鱼（goofish）的查找、比价、核验、批量收藏；任何品类的二手选品。**尤其是"当下就要做决定"的场景**——出配置单、挑一件生活物品、判断某条挂单值不值得下手。

**不适用（请用别的工具）**：蹲漏、等异常低价、7×24 监控推送——那是监控工具（如 ai-goofish-monitor）的活，两者的目标函数相反。

**不适用**：其他平台（虽然方法论可迁移，但 DOM 契约需要重写）；需要下单/付款的自动化（本 skill 只做到"加入收藏"，不碰支付）。

## 风险与免责

- 本 skill 提供的是**信息核验方法论**，不构成购买建议，也不保证任何交易结果。
- 二手交易有固有风险（假货、暗病、售后缺失）。**所有"证据"都可能被伪造**——文中判据是提高门槛，不是消除风险。
- 请遵守闲鱼用户协议与当地法律。批量操作请控制频率，避免触发风控。
- 登录态会持久化在浏览器 profile 里（这是磁盘凭据资产）。任务结束后如不希望保留，请主动退出登录或删除对应 cookie。
